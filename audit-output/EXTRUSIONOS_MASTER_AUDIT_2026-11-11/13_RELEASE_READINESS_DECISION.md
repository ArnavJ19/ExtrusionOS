# Release Readiness Decision

## NOT SAFE TO DEPLOY

This decision applies to the audited local candidate and to reliance on it as the sole operational record. It does not assert the linked production app and database run identical code. Selected hosted catalog and deployment observations are separately documented.

| Release blocker | Minimum evidence to change the decision |
|---|---|
| Affected Next.js/runtime dependencies | Intended lockfile and deployed runtime outside applicable vendor ranges, reproducible build, and targeted Auth, proxy, document and image/validation regression results |
| Casting mass and chemistry | Reproduced cases refused or corrected by approved domain rules. Measured good output, rejects, dross and loss reconcile to charge. Actual alloy/recipe revisions and independent approvals verified |
| Allocated versus issued billet basis | Partial issue reconciles with physical input. Invalid overconsumption fails. Unissued allocations are retained or returned explicitly. Independent-session completion and rollback verified |
| Candidate receipt import | Deposit stays a credit and indistinguishable receipts remain visible for approved review. Known-reference replay stays idempotent. Bank-to-accounts control totals and reversal verified |
| Inventory and packaging basis | Reserved kg agrees with the open reservation ledger. Packaging receipt, use and reversal reconcile to one stock basis by item, disposition and unit |
| Invitation-only controls and release drift | Vercel artifact, production alias, bound Supabase ledger/catalog and Auth configuration identified together. Approved signed-in role and Storage acceptance supports intended behavior |
| Physical and financial acceptance | Signed opening/control totals by location, lot/bundle, kg/pieces/metres, owner, scrap/WIP disposition and accounting period. Historical corrections and unresolved variances documented |
| Deployment and regression gate | Full intended release has a recorded reproducible result, ownership and migration rollback/forward plan. All release-blocking failures resolved and rerun against the final bound candidate |

The local quote oracle, the two fresh or upgrade replay checks, selected command behavior, and the document-number counter are supported within their tested boundaries. Separate database and operator evidence is required before declaring the broader release safe. [Test evidence](10_TEST_AND_PERFORMANCE_REPORT.md) · [Coverage](03_MODULE_COVERAGE_MATRIX.md)
